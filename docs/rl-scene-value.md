# 场面战力评估

2026-09-16 新增 `--scene-value`，检查点版本 `combat-benchmark-v1`。场面头使用独立战斗模拟标签，不以预测名次作为战力标签。主干、逐牌金币估值和动作 Q 保留，已有 `combat-economy-v1` 继续学习真实战斗与资源结果。

## 预测内容与动作选择

当前场面头从GRU记忆预测6项：胜率、败率、平率、预计造成伤害、预计受到伤害、下一次假想战斗中的淘汰概率。两项伤害训练目标为 `log1p(平均伤害) / log(41)`，没有按攻击力、身材或酒馆等级手工加总分。

另一个动作条件头预测执行该动作、按当前策略继续两回合后的同样6项指标。输入包含当前记忆、动作类型、来源实体、目标实体和放置位置。它预测的是在指定参照组上的未来战力，不是已经找到的最优两回合方案。

动作 Q 读取未来减当前的6项变化，以及变化与当前6项指标逐项相乘的结果。当前场面通过这个交互项影响不同动作的相对估值，避免给所有动作添加相同分数后被归一化抵消。一个读取当前记忆的线性层学习这12项信息对该局面动作回报的影响，因此血量和回合可以改变取舍；没有固定“战力胜率加几分”的奖励。评估输出到Q的连接停止梯度，防止Q回归直接修改战力单位；共享编码器仍接受两种损失。

融合层从零初始化，迁移初始完全保留旧策略概率与V，新增评估头需要训练后才有意义。旧参数和Adam动量保留。新增参数按当前头、动作条件头、目标投影、位置嵌入、融合层的顺序追加，保存/加载保持相同顺序。

## 独立模拟标签

沿用抽样的经济决策根局面，每个根最多8个候选动作。先从当时其他存活席位中确定性抽取最多3个参照对手，并冻结完整状态。所有候选的后续场面都对同一组参照阵容测试，避免比较时更换对手。

每个参照对手打4场，交替双方位置，使用配对种子。规则、英雄、随从能力、饰品、回合结束效果、护甲和伤害保护均由现有游戏引擎计算。全部操作发生在深拷贝上，不消费真实对局随机数、不修改真实牌池。当前局面和分支末端采用其各自实际回合及存活人数的伤害规则；被冻结的参照对手不是未来回合真实敌方阵容的预测。

分支仍先做4次随机续演，按原预算最多12次、默认向后2回合。在每次分支结束时另做上述战斗测试。若被淘汰，未来标签明确为失败/淘汰；达到计算截断而没有有效结果的比较不生成标签。当前头训练根局面与每个候选首条有效续演的公开末端观察，动作条件头训练每个候选全部有效续演的平均战力标签。当前胜负分布用交叉熵，伤害用Huber，淘汰概率用二元交叉熵，辅助损失系数0.1。

模型输入只有该席位的公开观察和自己的循环记忆。私有敌方阵容仅供模拟器生成标签，训练报告不导出参照对手私有状态。金币替换校准不重复运行这套战力基准，避免成倍增加费用。

## 与原有训练的关系

真实轨迹与分支 Q 仍学习最终奖励和短分支价值预测；本次增加了独立战力监督以及通往决策的连接，没有新增囤牌、刷新、购买或战斗胜率奖励。名次奖励及第8回合一次性升本奖励保持原配置。长期经济潜力目前仍依赖原资源辅助头、逐牌金币校准和后续对局回报，本次没有声称完成多回合经济价值的独立校准。

旧名次价值头不再是唯一的中途描述，但依然决定Q训练的长期目标。固定参照组可能被较强后期阵容全部击败，指标会饱和；抽样只有3个对手，也会有噪声。训练损失降低不等于对局强度提高，应继续观察真实对局。

## 构建与续训

`npm run build:scene` 生成单独的 `rl-dist/scene-evaluation.cjs` 和规则校验记录，不覆盖主模拟器。构建会检查战斗引擎依赖与原 `rl-dist/build.json` 哈希相同。运行时校验模拟器sourceHash，规则不匹配时失败。

在已有动作估值续训命令上加 `--scene-value`，或设置 `TAVERN_SCENE_VALUE=1`。需要已有 `--streaming --counterfactual --action-value`。新检查点要求新加载器；旧模型仍可作为历史对手。

多时间尺度训练使用 1、3、5 回合后继预测和按回合匹配的参照对手，见 [多时间尺度场面与经济预测](rl-multi-horizon.md)。
