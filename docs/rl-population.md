# 三条训练路线互相训练

`population` 同时运行多个独立 PPO 学习模型。每个模型有自己的权重、优化器、随机数状态和历史对手池，使用另外两条路线的冻结快照参与对局。

每条路线默认连续训练两轮，每轮 16 局，然后导入其他路线最新保存的检查点，再继续训练。交换发生在完成采样和 PPO 更新之后，一段训练中的对手保持固定。较快的模型可以继续前进，不等待较慢的模型完成同样数量的更新。

每个模型仍有四个学习席位，另外四席使用冻结对手。默认冻结席位的 60% 抽取自身历史模型，另外两条路线各占 20%。PPO 只更新当前学习模型产生的轨迹，三个模型的权重和轨迹不会直接合并。

## 启动

必须使用与三个检查点兼容的模拟器包。截止时间包含时区，下面的时间只是命令示例，实际运行应指定未来时间。

```bash
bash rl/run.sh population \
  --resumes /path/to/deep64.pt /path/to/deep256.pt /path/to/deep1024.pt \
  --output rl/runs/population \
  --deadline-utc 2026-09-11T11:30:34+00:00 \
  --workers 4 --iterations-per-exchange 2 --games-per-iteration 16 \
  --max-per-lineage 2 --external-fraction 0.4 --device cuda
```

`--workers` 是每个模型的模拟器进程数。三条路线各使用四个时，总共启动 12 个模拟器进程。模型保持检查点中的网络结构、学习率和序列批大小。所有子任务受同一个截止时间控制，失败时会停止该群体的其他子任务，保留已经保存的检查点和错误日志。

输入检查点保留不变，输出目录必须不存在。每条路线的 `initial.pt` 保留启动快照，`training/latest.pt` 保存最新完整更新。生成的 `exchange/latest.pt` 仅在对应训练段结束后替换，避免积累大型检查点文件。

每条外部路线最多保留两个不同权重版本。导入相同权重时不重复添加，也不重置原有困难度统计。池容量仍由原检查点的 `league_size` 控制，并至少保留四个可轮换历史位置。完整兼容性检查和抽样规则见[冻结对手池说明](rl-opponent-diversity.md)。

## 观察运行情况

- 根目录 `status.json` 记录三个任务的进程、当前阶段和交换轮次。
- `member-N/exchange-XXXX.json` 记录每次导入的来源局数、权重指纹和抽样概率。
- `member-N/training/metrics.jsonl` 记录该模型每轮 PPO 指标及对手实际出场次数。
- `member-N/training/manifest.json` 记录最新已保存局数和训练配置。

三条路线的训练局数和指标需要分别看，不能把对局中的相对名次当作共同进步的证据。评估继续使用独立的固定对手、种子及对局预算，不能用持续变化的训练对手池代替固定评估。
