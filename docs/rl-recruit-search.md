# 64、256、1024 层模型的当前招募回合搜索

搜索使用所选模型的策略头和价值头，权重保持冻结。每次只执行搜索选中的第一个动作，
下一次根据实际购买、刷新、发现等结果重新搜索。模拟范围是自己的当前招募回合，
到结束招募为止，不推进其他玩家或下一回合。结束回合效果通过规则引擎 `endEffects` 执行。

实现位于 `rl/recruit-search.ts`、`rl/python/tavern_rl/recruit_search.py` 和 `server/neural.ts`。
Python 使用 PUCT 选择分支，扩展一个节点后用策略网络采样后续操作，价值头评估末端。
每次显式评估结束招募作为比较基准；最终按已试算动作的平均价值选择。
当前 PPO 尚未学习搜索分布，小预算下访问次数容易被原策略的冻结/换位偏好支配，因此不直接按访问次数执行。
若预算只够评估结束基准、没有比较其他动作，则退回原策略，避免因为预算不足而强制结束。
不同随机结果形成不同子节点，回传的是同一玩家的价值，不做双人对弈的正负号翻转。
树中的每条历史拥有独立的 GRU 记忆；返回给真实对局的记忆只有根观察的一次更新。

## 回合结束和计算预算

- 玩家点结束只锁定自己的操作，所有存活玩家和人机都结束后才提前进入战斗。
- 训练模式不设招募倒计时，会等待未完成的人机。
- 烧绳模式在截止时间直接开战；旧回合的迟到搜索结果会被丢弃。
- 单次搜索最多 32 次模拟、128 个树节点、每条模拟最多 64 步，时间预算最多 1000 毫秒。
  这是计算预算，不是实际回合的操作次数上限。截止检查在同步模拟/推理调用之间进行，
  单个调用可能使实际耗时稍超预算。
- 烧绳模式按剩余时间和未完成的人机数缩短预算，预留最后 2 秒，临近结束只用模型直接决策。
  单个服务仍串行处理请求，多房间并发时不能保证每个人机都完成全部计划。
- 搜索版移除了在线人机原有的 64/96 次操作限制。普通模型的原有行为保持。

每个人机每回合最多切换冻结状态 2 次、换位 6 次。冻结与解冻共用次数；换位按插入一次计数，不能立即恢复上一次换位前的完整站位，也不能执行不改变位置的动作。出牌时选择位置不计作换位。普通模型、搜索模型和默认自我对战使用相同规则，玩家操作不受限制。

次数保存在每席位的游戏状态，重连和服务器恢复不会重置，下一回合恢复。公开实体包含剩余次数和用槽位编号表示的上次换位前顺序。搜索从这些实际剩余次数开始，每条分支在自己的状态副本上消耗，重置模拟恢复根状态，模拟不会消耗真实玩家的次数。

原先在线搜索为防循环而保存的 128 个局面哈希已由这套计数和立即撤销检查替代，省去逐候选克隆与整份观察哈希。Python 搜索内部仍有重复局面截断，用于防止其他无收益循环。实现和兼容边界见 [人机动作限制](ai-action-limits.md)。

## 信息范围和近似

搜索输入只有现有模型的公开 `entities`、合法动作和自己的记忆，不传完整 Game、房间快照、
真实剩余卡池、对手当前阵容/手牌或真实随机数状态。对手历史仍只有公开的最近两场记录。

独立模拟器用公开卡牌的星级库存减去可见的己方持牌来估计卡池。
它尚未估计其他玩家的持牌、生成牌来源或磁力牌的库存来源，刷新概率只是近似。
根节点还与服务器提供的真实合法动作取交集，执行时再次由真实规则校验。

未展示的待处理发现、英雄技能选择中的未公开历史，以及需要当前敌方战队的斯卡布斯技能，
不能可靠还原时直接使用原策略，并在响应里说明原因。模拟途中遇到无法处理的技能选择则截断评估。
这不是完整的不完全信息游戏求解器。

价值头仍是原 PPO 的价值头，回合结束后的估值也只是近似。训练现已增加独立的[金币方案比较目标](rl-gold-planning.md)，不直接拟合这里的 PUCT 访问分布；
搜索动作不能按原策略采样动作直接用于现有 PPO 更新。功能和时延验证不能证明棋力提升。

## 构建和运行

```bash
npm run build:search
npm run test:search
PYTHONPATH=rl/python .venv/bin/python -m tavern_rl.serve model.pt \
  --port 18896 --search-bundle rl-dist/recruit-search.cjs \
  --search-ms 1000 --search-simulations 32
```

`model.pt` 是通过 `scripts/export-inference.py` 导出的 64、256 或 1024 层推理文件，要求 `scouting-v4` 合约匹配。
模型注册表中为这一服务单独添加 `search: true` 的条目，健康检查还会核对搜索协议版本。
日常 `tavern-ops.py publish` 更新普通模型时保留这一独立冻结的搜索版本；搜索权重需单独验证后更新。
搜索服务使用同一份模型处理所有分支，树不落盘，每次决策后释放。
构建写入独立的 `rl-dist/recruit-search.cjs`，不覆盖训练中的冻结模拟器。

公开局面验证工具：

```bash
npx tsx scripts/recruit-search-fixtures.ts > /tmp/search-fixtures.json
PYTHONPATH=rl/python .venv/bin/python -m tavern_rl.search_benchmark \
  model.pt /tmp/search-fixtures.json --bundle rl-dist/recruit-search.cjs \
  --output /tmp/search-validation.json
```

服务单元为 `deploy/tavern-deep64-search.service` 和 `deploy/tavern-deep64-search-tunnel.service`。
计算服务在现有计算机上运行，单元上限为 1 个 CPU 核、1 GiB 内存，Node 老生代堆上限 192 MiB。
公网回环端口 18897 通过 SSH 转发到计算机的 18896，不向互联网直接开放推理端口。

2026-09-15 已部署独立选项“64 层模型＋回合搜索（实验）”，使用当时线上 2568 局的冻结权重。
三组公开局面验证中单次请求约 0.6～1.1 秒；隔离房间的单个人机前三轮分别约 1.2、5.2、8.5 秒结束。
这些时间不能直接当作满房、多房间并发的保证。部署与测试记录见
[rl-recruit-search-deployment-20260915.json](rl-recruit-search-deployment-20260915.json)。

算法背景见 [AlphaZero 论文](https://arxiv.org/abs/1712.01815) 与
[信息集 MCTS 论文](https://eprints.whiterose.ac.uk/id/eprint/75048/)。这里的库存近似、当前回合边界和循环处理是项目实现选择。

2026-09-15 已为 256 和 1024 层增加独立搜索选项。冻结权重分别沿用线上 2140 局和 1284 局版本，未用正在训练的检查点替换。256 层在三个公开局面完成 17、3、3 次模拟，单次约 1.02～1.06 秒；1024 层完成 6、3、2 次，约 1.08～1.13 秒。时间预算 1000 毫秒在同步调用之间检查，因此实际请求可能略超出。

新增计算端口 18900、18902，经 SSH 转发到公网回环端口 18901、18903。服务分别限制为 1 个 CPU 核和 1/2 GiB 内存。它们只在玩家选用时处理搜索，不占新 Blackwell 训练服务器。全部六个模型选项通过浏览器测试，两种新搜索模型的隔离房间前三回合均正常结束。搜索代码已移除金币扣分公式，不以系数为零来保留该分支。记录见 [深层搜索部署](rl-deep-search-deployment-20260915.json)。
