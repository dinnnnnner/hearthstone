## 训练迁移与恢复

旧四小时任务在此次切换前已经失败，1024 层的采样进程报 `Illegal action 3750 for seat 4`，其他学习进程随后被协调器停止。失败快照为种子 2177、第 10 回合；非法动作没有写入 PPO 更新。

检查采样代码时，在同一 Blackwell 上复现了 GPU FP32 累计概率跨越零概率区间时出现一个浮点单位的跳变。二分查找会把精确落在该边界上的随机数映射到非法动作。复现中动作 60 的概率为零，累计概率却从 `0.18875880539417267` 增至 `0.18875882029533386`。原失败没有保存概率张量，不能据此还原那一次采样的所有数值。

采样现在从合法动作中选择第一个超过随机数的累计概率位置，并保护末尾舍入边界。每局、每席的独立随机数流保持原有设计，PPO 保存的是最终合法动作对应的对数概率。没有给非法动作编造奖励，也没有跳过失败对局继续更新。

在独立 `smoke` 目录完成了两局完整自我对战和一次 CUDA PPO 更新，启用多进程采样、采样图、训练图和融合 Adam。此测试检查点没有替换正式迁移检查点。随后在北京时间 14:27 恢复三模型混合训练，仍按原定 **15:50:39** 停止，没有重新计满四小时。

每个模型仍为 64 个模拟器、8 个采样进程，每轮 64 局、每两轮交换历史对手。学习率、第一名额外奖励、英雄池和历史对手比例沿用原配置。每 300 秒的巡检绑定新任务 `/root/tavern-ops/20260915-action-limits/resume.json`，结果位于该任务的 `health` 目录。

本地 Python 测试共 142 项，通过并跳过 5 项仅限 CUDA 的测试。新增的采样边界与迁移测试另在 Blackwell 上全部通过，其中包含 GPU 零概率跳变回归。规则与在线服务的既有完整测试记录见 [源码验证](ai-action-limits-validation-20260915.json)。这些是正确性与运行验证，不是棋力评估。
