# 棋盘与战斗表现改版

基于 `baseline-demo-2026-09-08`，在 `feature/gameplay-presentation` 分支开发。旧标签、Git bundle 和服务器归档保留，存档键仍为 `bobs-tavern-season14-v1`。本次改动集中在表现与输入层，没有扩充当前赛季技能覆盖，也没有加入 RL 训练。

参考的重点是共同棋盘、上方鲍勃、椭圆随从、下方英雄及手牌、侧边操作、拖牌和逐次攻击反馈。棋盘边框是本项目绘制的 SVG，卡牌继续使用已有原画，没有把视频截帧作为游戏背景。

## 实现

`GameTable` 读取 `Game` 和 `Battle.frames`，通过 `Action` 回调执行购买、打出、站位和技能操作。招募结束后，用同一棋盘显示战斗快照。详情、三连发现、黑暗发现与饰品选择继续调用已有规则及弹窗。

`presentation.ts` 比较相邻快照，区分伤害、增益、圣盾破碎、召唤和死亡。Web Animations API 播放攻击和站位位移，Canvas 只在有粒子时运行，像素比上限为 1.5。音效复用一个 AudioContext；没有音频下载，浏览器不支持或拒绝音频时不影响游戏操作。减少动态效果的系统偏好会关闭位移动画和粒子。

选择这套实现是因为当前玩法是固定棋盘上的卡牌交互，已有 TypeScript 规则和 React 控件可以直接复用。本次没有引入 Phaser、Pixi 或其他引擎依赖。后续更换渲染器时，仍可使用同一组动作和战斗状态；训练模式需要进一步提供不生成战斗快照的运行路径，见 [RL 记录](rl-roadmap.md)。

手机通过 Pointer Events 区分拖牌与横向手牌滚动，提供点选操作作为另一条完整操作路径。旧版面板保留在设置中，新旧界面共用存档。

## 验证范围

- 原有 45 个规则测试，覆盖有限牌池、三连、技能和战斗；新增 1 个快照差异测试，检查输入状态不被表现逻辑修改。
- 原有 12 个界面测试明确运行旧版面板，继续覆盖回退布局。
- 新棋盘测试覆盖鼠标拖动购买、出牌、站位、出售，冻结与战斗播放，技能目标，三连奖励，布局切换和存档。
- 手机测试覆盖 390 × 844 与 844 × 390、七随从和十手牌，通过浏览器原生触摸事件检查纵向拖牌与横向滑动。
- 发布测试检查大厅进入酒馆、子路径素材、返回大厅后存档和 SECTOR WebSocket。

这仍是当前赛季的部分复刻。战斗表现来自现有引擎快照，尚未复刻官方所有触发顺序、动画、语音、交互细节和完整八人 AI 经济。大数值用 K / M 缩写显示，精确数值保存在规则状态和卡牌详情中。
