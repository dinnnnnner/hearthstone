## 实现

`GameTable` 读取 `Game` 和 `Battle.frames`，通过 `Action` 回调执行购买、打出、站位和技能操作。招募结束后，用同一棋盘显示战斗快照。详情、三连发现、黑暗发现与饰品选择继续调用已有规则及弹窗。

`presentation.ts` 比较相邻快照，区分伤害、增益、圣盾破碎、召唤和死亡。Web Animations API 播放攻击和站位位移，Canvas 只在有粒子时运行，像素比上限为 1.5。音效复用一个 AudioContext；没有音频下载，浏览器不支持或拒绝音频时不影响游戏操作。减少动态效果的系统偏好会关闭位移动画和粒子。

选择这套实现是因为当前玩法是固定棋盘上的卡牌交互，已有 TypeScript 规则和 React 控件可以直接复用。本次没有引入 Phaser、Pixi 或其他引擎依赖。后续更换渲染器时，仍可使用同一组动作和战斗状态；训练模式需要进一步提供不生成战斗快照的运行路径，见 [RL 记录](rl-roadmap.md)。

手机通过 Pointer Events 区分拖牌与横向手牌滚动，提供点选操作作为另一条完整操作路径。旧版面板保留在设置中，新旧界面共用存档。

## 第二轮动画调整

继续对照上述实战片段的连续帧。`motion.ts` 统一动画时刻，普通攻击在 130 ms 完成蓄力、270 ms 接触、345 ms 完成受击回弹，610 ms 回到原位。攻击快照停留 740 ms，结算快照停留 440 ms。以上为本项目按片段观感调整的参数，不是官方客户端提取的精确参数。

引擎快照在攻击结算后生成，表现层在接触前暂时显示上一帧的生命、攻击和圣盾，接触时才揭示新值。伤害使用黄色爆裂形数字，攻击者的数字随回位移动。圣盾扩散成光圈与碎片，死亡棋子分成三块退场，随后出现亡语或复生随从。最后用英雄撞击播放战斗伤害，对手头像和侧边血量在接触时更新。

购买、出牌和出售使用原位置到目标区域的飞行过渡。三连只收集实际被合并的三张牌，汇聚后进入手牌；刷新先收起旧随从，再依次展示新随从。快速操作可以中断过渡，结算不会等待动画完成。

`SceneTimeline` 同时管理位移、延迟伤害和临时节点。暂停冻结待触发效果、数值和粒子，倍速同步调整动画时钟；跳过清空临时节点与粒子。减少动态效果模式直接显示结果。没有修改技能、牌池或 AI 决策逻辑。

新增浏览器检查使用固定战斗帧验证接触前后的数值和圣盾、暂停后的位移不变、倍速与跳过清理，以及播放控制不会改写规则状态。18 个本地界面测试通过，规则与状态测试仍为 46 个。

第二轮发布目录为 `/var/www/playroom/releases/20260908T051012Z`。公网另通过 4 个浏览器检查，包括接触时刻、暂停和跳过的验证，以及大厅、手机和 SECTOR WebSocket。Nginx 验证通过，SECTOR PID 仍为 106565。JavaScript 的静态 gzip 文件为 212,866 字节。上一版棋盘发布和更早的 demo 基线均保留。

## 加载与画面细节

首屏加载样式和 SVG 纹章内联在 HTML 中，入口脚本尚未下载时即可显示。React 挂载后淡出首屏，再进入游客大厅或当前棋盘素材准备画面。加载进度来自图片完成或失败事件，每次最多三个请求；三秒后提供先进入的操作，八秒后自动结束等待。战斗播放在准备期间暂停，避免开场动画在遮罩后播放。

棋盘使用 SVG 渐变补充木板和皮革的明暗、铆钉与刻纹。卡牌悬停只缩放内部图片，避免覆盖战斗使用的棋子位移。按钮增加按压和键盘焦点反馈，桌面悬停效果只对精确指针启用。新增加载和淡入动画遵守减少动态效果设置，没有增加图片下载或常驻服务。

版本和验证记录见 [加载画面更新记录](checkpoints/loading-details-2026-09-08.md)。
