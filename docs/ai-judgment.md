# 人机对战逐牌估值

2026-09-17，本地实现并验证，尚未部署。

人机对战上方的“AI 判断”开关显示玩家自己的动作概率、场上逐牌贡献、酒馆随从和手牌估值。桌面牌桌、面板模式及手机宽度均支持。默认关闭，关闭时不请求推理。

`src/minion-evaluation.ts` 是共用的逐牌评分入口。训练基线 `rl/basic-evaluation.ts` 和界面服务 `server/judgment.ts` 都调用它。当前权重和原训练基线的数值保持一致：

- 基础身材为当前攻击加生命。
- 圣盾加当前攻击，风怒加当前攻击的一半。
- 复生加原始攻击与 1 点生命之和的一半；金色牌使用金色原始攻击，避免重复计算后加的身材。
- 场面分严格等于场上逐牌分的总和。酒馆牌不计入持有资产或场面，手牌按基础分的 25% 计潜力。
- 当前金币、基础出售资产、下一回合收入、免费刷新、法术折扣、酒馆等级机会分继续使用原经济模块，单独展示。

规则分不是金币等价、胜率或预期名次。已应用的增益由当前攻防体现，不再给增益来源重复加分。战吼在真实打出后通过新局面体现；亡语、触发型成长、阵容配合和依赖对手的关键词没有可靠的静态估分，会在卡牌详情说明。酒馆基础分不预测打出、替换或三连后的整套收益。

动作概率来自本房间选定的模型，服务端只接受登录玩家当前的局面版本。接口按真实规则筛选操作，并使用模型的公开观察编码；私有对手场面只供规则合法性检查。判断使用零历史记忆，未重演玩家此前操作。搜索模型请求 `search: false`，只显示策略概率。概率与规则估值分开显示，旧的神经网络金币估值头没有恢复。

同一玩家相同局面合并请求并缓存，变化中的局面每次最多一个推理请求。自己的操作、阶段变化和公开对手信息更新会使结果失效，其他机器人单纯改变牌池不会触发反复请求。推理异常保留规则估值，不执行动作或触发脚本代打。脚本模式只提供规则估值。

训练使用共用源码后，需要重新构建训练包。虽然本次保持原分数，代码抽取和返回字段增加仍会改变 basic implementation hash；不得覆盖旧训练包或绕过续训时的指纹校验。本次未重建服务器训练包或更新线上模型。后续已在本地实现逐牌学习网络及搜索势函数还原，见 [新架构说明](rl-ledger-model.md)；旧线上导出仍需从完整检查点重新导出并部署匹配评分器。

验证：`npm run build`，`npm run test:server`，以及本地确定性推理服务下的 `tests/judgment.spec.ts`、`tests/spectator.spec.ts`。浏览器验证涵盖开关、买牌到手牌、打出后逐牌加总、两个界面模式与 390px 布局；模拟概率用于检查界面和接口，不用于评价真实模型强弱。
