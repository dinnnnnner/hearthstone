# Rust 战斗原型实测

2026 年 9 月 18 日，本地完成独立 Rust 战斗原型。源码与复现命令见 [实验说明](../experiments/rust-combat/README.md)，逐轮测量和源码校验值见 [原始报告](rust-combat-prototype-20260918.json)。没有接入正式训练或线上服务。

## 正确性

TS 对照直接调用现有 `seasonCombat`。33 个边界场景及 10,000 个随机场景共包含 49,907 次攻击，攻击目标、死亡结算前后阵容、复生属性和位置、存活阵容、伤害及随机数状态全部一致，没有差异。

六项 Rust 单元测试、四类非法请求检查、Clippy 严格检查和 TS 类型检查通过。当前支持六种基础随从及嘲讽、圣盾、风怒、潜行、剧毒、烈毒、复生；未支持的卡牌、效果字段和关键词直接报错。

## 性能

测试机器为 Intel Core Ultra 7 270K Plus。双方绑定同一个 CPU 核，以相同的 256 个非空随机阵容预热五遍，再交替运行各五轮，每轮 25,600 场战斗。关闭动画帧记录，以下为五轮中位数。

| 指标 | 生产 TS 引擎处理基础子集 | Rust 基础子集原型 |
| --- | ---: | ---: |
| 核心计算耗时 | 5.819 秒 | 0.01412 秒 |
| 战斗数/秒 | 4,399 | 1,813,377 |
| 整个进程耗时 | 6.679 秒 | 0.01650 秒 |
| 进程峰值 RSS | 180.7 MiB | 2.98 MiB |

核心计时不含启动、解析输入、准备局面、预热和 Python 通信，包含战斗内部阵容复制。进程耗时包含这些启动和准备成本。RSS 使用进程自身 `/proc/self/status` 的 `VmHWM`；`wait4` 在本环境会混入启动父进程的历史高水位，因此不采用它作为内存结论。

表中核心耗时相差约 412 倍。这不是同等完整实现的语言对比：TS 保留完整事件分发框架，Rust 仅实现经过对照的六种基础随从和关键词。实验输入也不是实际训练阵容分布。这个数不能作为完整引擎迁移或训练加速的预期。

## 结论与下一步

原型证明基础战斗可以用 Rust 重现，并具备较低的运行时和内存成本。完整迁移是否划算还没有定论。

接下来应覆盖死亡队列中的召唤连锁、亡语、光环和饰品，每次扩展都继续与 TS 逐步对照。具备真实阵容覆盖后，再通过 Python 原生接口接入隔离采样任务，比较固定工作量下的整轮采样耗时、有效训练样本数和内存。GPU 推理、优化器及保存检查点的时间仍需单独统计。
