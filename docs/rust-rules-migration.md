# Rust 规则迁移进度

目标是训练、在线房间和网页练习共用 Rust 规则。当前迁移未完成，实际对局和训练仍由 TS 引擎运行，尚未部署或切换默认入口。

已建立共享 Rust crate、Python 原生接口、Node 与浏览器 WASM 接口，并导入完整数据目录。目录包含 1,632 个卡牌定义，当前候选池包含 242 个随从、66 个法术、89 个英雄、20 个黑暗之赐、237 个饰品。导入定义不表示所有效果已实现。

已迁移并与现有 TS 比较的规则包括卡牌创建、点金、三连属性继承、复制技能、全局属性同步、购买和刷新费用、有限卡池抽取、目标筛选、英雄技能状态和更换、黑暗之赐资格和附加效果、饰品候选及报价。

40,747 个对照用例分别经过 Python 原生库、Node WASM 和真实 Chromium 浏览器执行，三端零差异。比较内容包括返回状态、错误和随机数状态。另有 9 项 Rust 测试，检查内存所有权、非法输入、卡池守恒、爆牌退池、跨批恢复、递归触发和未迁移路径的拒绝。详见 `rust-rules-parity-20260918.json`，使用 `npm run test:rust` 可重新生成本地报告。

本次新增 `recruitBatch`，可在 Rust 内连续执行发现队列、三连匹配、入手效果、奖励、退池和属性联动。招募效果分发已实现 37 类，并接入战吼重复、战吼后触发及递归深度限制。修复了来源随从先增益自身后，后续目标读取旧属性的问题，以及三连时黑暗之赐回合应随第一个赐福继承的问题。

仍需迁移招募玩家动作、其余效果和完整战斗事件、英雄技能效果、饰品持续效果、黑暗之赐触发、古神、经典模式规则、八人环境、观测和合法动作，以及三个实际应用入口。当前整局操作会明确返回 `RUST_ENGINE_INCOMPLETE`。部分规则通过对照测试不能代替整局验收。

构建方式、已实现命令和后续验收条件见 [native/README.md](../native/README.md)。
