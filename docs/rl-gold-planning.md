# 金币规划训练

训练在普通 PPO 之外增加回合内方案比较。它用当前权重估计几种花钱路线的结果，再用这些比较更新策略。不会规定固定的升本回合，也不会扣除回合结束剩金币的奖励。

## 一批训练怎样运行

1. 正常采样完整八人对局，保留实际动作、原策略概率和每席位 GRU 记忆。只有学习席位进入 PPO。
2. 每席每回合保留第一个有金币且能进行经济操作的公开局面候选。用确定性优先级抽取最多 32 个局面，多进程合并后仍是总计 32 个。抽样不消耗游戏和策略的随机数。
3. 每个局面最多比较 7 种起手，包括直接结束、升本、两种买随从、买法术、刷新和一种出牌。即使旧模型几乎不给升本或买牌概率，这些类别也有试算机会。
4. 每种起手使用相同的 3 个随机种子，各自继续模拟最多 32 步招募操作。实际引擎计算每步的费用、折扣、买卖、出牌和刷新结果。
5. 完整结束的方案用当前冻结价值头估值，按 3 次结果的均值比较，不取刷新后的最好结果。只有全部 3 次完成的起手进入标签；预算耗尽、无法重建和边界状态不会变成虚构的负分或强制结束标签。
6. 先执行正常 PPO，再用规划标签执行两轮额外的策略更新。此后保存完整检查点，把更新后的权重加入历史池。

规划是有限的策略引导试算。续走时按动作类别的总概率选择，再选类别内概率最高的动作；不展开换位，仍按当前牌面执行买卖、出牌等操作。有合法买牌时暂不选冻结，收尾阶段可选择冻结。候选数量和续走方式都有限制，并非穷举金币的所有最优分配。

## 标签和优化

平均价值差小于 0.02 的比较不产生训练标签。其他比较将价值均值除以温度 0.15 后做 softmax，并与旧策略在被比较动作上的条件分布各混合 50%。额外损失只比较这些动作，不把没有完成试算的动作当成错误答案。

规划使用采样时保存的公开局面、操作前记忆和上一个动作。分支更新自己的记忆，不会污染真实对局或其他分支。额外更新使用同一 Adam 优化器，只走策略计算，不向价值头写入伪造的回报；共享编码器仍会更新。名次奖励保持第一名 +2、第八名 −1。

PPO 的轨迹始终来自原策略采样。搜索动作和搜索概率不会替换真实轨迹，所以不会将搜索策略的数据冒充为普通 PPO 的策略样本。这也不同于直接蒸馏在线 PUCT 的访问次数。

## 计算与记录

独立 Node 进程从公开局面建立批量分支，不接收真实卡池、对手私有棋盘或游戏随机状态。每批最多 96 个分支，模型推理每个 GPU 小批最多 32 个局面。深层网络可使用残差塔 CUDA Graph，图在更新参数前释放。

检查点配置保存 `gold_planning` 和累计 `gold_planning_updates`。每轮日志的 `gold_planning` 字段记录抽样局面、候选类别、完整与截断方案数、标签数、偏好的起手、耗时及额外更新次数。`gold-planning-000193.json` 这类文件保存部分路线的动作与剩余金币，以及标签对应的方案价值和目标分布。

启用新训练或从完整检查点续训：

```bash
bash rl/run.sh train --resume path/to/latest.pt --output path/to/new-run \
  --gold-planning --planning-states 32 --device cuda --workers 64 \
  --sampling-processes 8 --fused-adam --training-graphs
```

旧协调器可通过 `TAVERN_GOLD_PLANNING=1` 启用，随后设置保存在检查点中。省略参数会沿用已保存的设置；`--no-gold-planning` 明确关闭。游戏规则、动作编码和网络结构未改变，训练模拟器哈希仍为收尾冻结版本。训练包中需使用支持 `gold-rollout-v1` 批量接口的 `recruit-search.cjs`，启动时检查接口和观察契约。
