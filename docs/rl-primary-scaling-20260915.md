# 单主模型与并行采样测试

这次实现此前提出的三项组合：只更新一个主模型、增加实际并行环境和每轮局数、使用已经验证的 CUDA Graph 采样。速度测试使用 256 层模型，没有进行三个模型的棋力比较。

## 已接入的操作

```bash
python3 scripts/tavern-ops.py train --hours 2 --model 256 --workers 64 --games 64
```

协调器只为 256 层启动混合对手池和 PPO 进程，64、1024 层的完整检查点继续作为冻结对手。历史对手数量、外部对手占比、第一名额外奖励、剩余铸币惩罚沿用现有设置。每轮先收集 64 局，再执行 PPO。

`--model` 也支持 `64`、`1024` 和 `all`。未指定新增选项时仍是三个模型、各 16 并行、每轮 16 局。`--games` 小于 `--workers` 会在连接服务器前被拒绝。

协调器补丁在 `scripts/enable-primary-learner.py`，服务器备份在 `/root/tavern-scaling-20260915/coordinator-backup`。测试验证了选中模型、冻结对手、保持三模型默认行为、停止子进程和非法成员拒绝。

## 采样短测

256 层单独运行，使用同一份检查点、历史对手和 64 个种子，每局执行 256 步。CUDA Graph 始终启用。按 16、32、64、16 并行顺序测试，16 并行基线取首尾均值。

| 并行数 | 动作/秒 | 平均有效推理批量 | 相对 16 并行 |
|---|---:|---:|---:|
| 16 | 161.41 | 2.63 | 1.00 倍 |
| 32 | 179.24 | 3.83 | 1.11 倍 |
| 64 | 190.76 | 6.35 | 1.18 倍 |

全部配置、全部种子的动作回放一致。64 并行相对 32 并行的额外收益约为 6.4%，并行数翻倍没有使速度翻倍。

此前三模型同时运行、16 并行、未启用 CUDA Graph 的短测中，256 层约为 67.06 动作/秒。这次单模型 64 并行约为该值的 2.84 倍。两次短测的总对局数不同，这个对比只说明采样吞吐，不能直接换算完整训练耗时。

## 完整训练验证方法

从同一个正式检查点分别启动一次独立的 16 局和 64 局训练，包含完整对局、真实 PPO 更新及检查点写入。结果写入测试目录，正式训练检查点保持只读。记录整个进程的耗时、每轮耗时、优化器更新次数、KL 提前停止、显存和内存。

扩大每轮局数会改变 PPO 更新间隔；应同时查看优化器更新次数和有效样本数，不能只用累计局数推断棋力。长期训练保持停止。服务器原始日志和脚本位于 `/root/tavern-scaling-20260915`。

16 并行的完整测试收集了 16 局、33670 次环境决策和 19438 个学习样本。采样 354.34 秒、PPO 104.39 秒，共执行 156 次优化器更新，没有触发 KL 提前停止。进程总耗时 488.29 秒，包含启动及检查点读写，约 117.96 局/小时；仅按采样和更新所在迭代计时则约 123.80 局/小时。

原三模型训练最近三轮的 256 层迭代耗时平均为 742.58 秒，每轮 16 局，约 77.57 局/小时。该历史指标不包含进程冷启动，与本次进程总吞吐的口径不同；比较时应分别列出，不能把启动开销混入一侧。

## 完整结果

| 配置 | 每轮局数 | 每轮采样与 PPO 等耗时 | 按迭代计时的局数/小时 | 相对原配置 |
|---|---:|---:|---:|---:|
| 原三模型、16 并行，近期日志 | 16 | 742.58 秒 | 77.57 | 1.00 倍 |
| 单 256 层、16 并行、CUDA Graph | 16 | 465.26 秒 | 123.80 | 1.60 倍 |
| 单 256 层、64 并行、CUDA Graph | 64 | 1503.65 秒 | 153.23 | 1.98 倍 |

64 并行完整收集了 64 局、132156 次环境决策、76646 个学习样本。采样用了 1060.97 秒，PPO 用了 436.19 秒，执行 614 次优化器更新，平均近似 KL 为 0.01017，没有触发提前停止。两组均按原配置完成两轮 PPO。

64 并行从进程启动到退出实际用了 1538.02 秒，含读写，约 149.80 局/小时。按这个短测速度保持不变估算，从当前 2268 局达到 10 万局约需 27 天。基线是历史三轮日志，新配置只测了一次完整迭代，尚未验证长期吞吐和棋力变化。

完整测试的峰值 PyTorch 张量显存约 2.26 GiB，定时监测的容器总内存峰值约 17 GB。正式三个检查点哈希保持一致，测试用检查点已删除，长期训练和测试进程均已停止。
