# 离线自博弈训练进展

2026-09-10 已实现第一版八人神经网络自博弈 PPO，使用项目共享规则，无需重写前端或线上收集数据。安装、训练、续训、评估和回放命令见 [训练说明](../rl/README.md)。

## 已实现

- `rl/environment.ts` 提供 `reset / step / view / legalActions / snapshot / restore`，八席位均为策略席位，禁用脚本人机和自动选择，使用共享牌池、双方交战、淘汰及幽灵配对。
- 训练作用域接管 UID、随机数和逻辑时间，关闭帧记录与界面日志，正常服务器仍使用安全随机身份。
- 只编码玩家可见信息，动作使用稳定槽位编号。合法性预检不消耗游戏随机数或实例序号。
- PyTorch 实现动作掩码、actor、critic、每席位 GAE、clipped PPO、KL 提前停止和梯度裁剪。
- 多个本地 Node 进程采样，Python 批量推理。随机网络自博弈起步，加入冻结历史池，只用当前策略轨迹更新。
- 保存完整更新轮检查点、优化器、历史池和随机状态，支持规则哈希校验、续训、历史对手评估和种子动作回放。
- `npm run package:rl` 生成独立训练包，不含网页图片或在线数据。

## 下一步

1. 修复大量采样暴露的规则缺陷，补齐官方差异。当前覆盖见 [rules-coverage.json](rules-coverage.json)。
2. 增加英雄选择训练，完善附加效果和历史信息表示，再尝试卡牌 embedding、序列模型与组合动作策略。
3. 固定对手和保留种子做长期评估，扩展历史对手采样。短测试不能证明棋力。
4. 根据租用机器实测优化模拟器、通信和采样内存，再考虑多机采样。当前不是分布式系统。
5. 得到可信评估结果后再接入线上推理和超时降级，目前网站人机保持原实现。

Demo 基线为 `baseline-demo-2026-09-08`，四选一英雄房间版本为 `hero-draft-2026-09-10`。本轮完成训练基础设施，不代表已经训练出高手人机。
