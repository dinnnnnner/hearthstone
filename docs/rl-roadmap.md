# 后续 AI / RL 接入记录

当前只保留需求与接口设计，没有实现训练器，也没有改变规则引擎。起点为 `baseline-demo-2026-09-08`。

## 已有基础

`src/engine.ts` 的 `createGame(heroId, rng)` 创建状态，`act(state, action, rng)` 执行动作并返回新状态或错误。`Game` 与 `Action` 已与 React 界面分离，当前赛季逻辑位于 `src/season/engine.ts`。`assertPool` 和已有测试可以帮助发现环境执行时的牌池错误。

## 建议的训练环境接口

- `reset(seed, hero, ruleset)`：初始化一局，返回玩家可见观察。
- `observe(player)`：返回金币、等级、生命与护甲、己方阵容、手牌、酒馆及可见对手信息。
- `legalActions()`：列举完整合法动作及目标，生成动作掩码。
- `step(action)`：推进状态，返回观察、奖励、终止标记和调试信息。
- `snapshot()/restore()`：保存或恢复游戏状态、随机数状态与实例序号。

界面和策略都通过同一组动作驱动引擎。模型输入使用卡牌 ID、区域索引、属性及关键词，避免直接把图片或不稳定的实例 UID 当作基础特征。

需要明确定义：购买后是否立即进入下一决策，发现/定向技能是否拆分动作，以及战斗播放用的 `continue` 是否由环境自动执行。非法动作不能让策略通过无成本循环拖延一局。

## 训练前必须补齐的差异

1. **可复现性。** 随机抽取已能传入 RNG，但 `uid()` 仍读取 `Date.now()`、全局计数与 `Math.random()`；相同种子目前不能得到字节完全一致的状态。应将 ID 计数和随机数状态放入环境，并验证存档后继续执行能复现。
2. **对局完整性。** 当前七名 AI 使用简化招募，没有完整经济、三连、英雄技能及 AI 互相交战。先补齐八人回合与淘汰流程，或者明确把任务限制为招募练习，不能把现有胜率当作正式八人对局水平。
3. **观察边界。** 内部状态含完整牌池和其他玩家阵容。策略只能看到所定义规则允许的信息，不能直接把完整 `Game` 当作正式对局观察。
4. **事件与奖励。** 统一复杂技能的触发顺序，测试结算与有限牌池守恒。正式对局优先使用终局排名奖励；购买数量、属性增长等奖励可能鼓励偏离获胜目标的策略。
5. **运行成本。** 训练需要关闭逐帧战斗记录、界面日志和图片加载，支持无界面批量推进。当前 `Battle.frames`、大状态复制和日志是练习界面的实现，不能直接当作高吞吐训练环境。
6. **版本锁定。** 每个训练产物记录规则版本、随从池覆盖、种子、观察和动作编码版本及代码提交；分别评估固定对手和未参与训练的对手。

可先建立随机合法策略和规则策略作为基准，再加入可学习策略。后续棋盘与动画改造应留在表现层，使同一规则引擎可以同时供人玩和供 AI 使用。

## 在线房间补充

新增 `server/rooms.ts` 的八席位服务器对局，包含统一牌池、双方战斗状态、人机合法动作策略和淘汰后幽灵配对。该协调器可作为后续训练环境的对局流程参考，但还没有实现 `reset/step/observe/legalActions` 训练接口。当前人机是规则策略；UID、随机数可复现性和官方规则覆盖仍需按上文继续处理，不能视作已训练的 RL 人机。

## 2026-09-10 常规池扩充

常规 1 至 6 星池已接入 234 张随从、67 张酒馆法术，英雄为 89/116 位。缺失英雄、黑暗之赐和饰品限制见 `rules-coverage.json`。训练时应把这一覆盖范围写入环境版本，不能用卡牌条目齐全推断官方规则已经齐全。

动作编码需要支持抉择的 `discover` 与可选 `target`，同时为锁定手牌生成正确的合法动作掩码。英雄技能新增各自的购买进度、冷却与永久使用次数；第二技能和主技能不可共用进度。刀油通过 `actSeason` 的私有上下文获取匹配对手战队，只向玩家返回发现候选，训练策略也应遵守相同信息边界。
