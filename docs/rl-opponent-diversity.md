# 冻结神经网络对手池

训练可以导入其他独立训练路线的检查点。默认四个席位使用当前模型，另四个席位抽取冻结模型。PPO 只使用当前模型的轨迹，冻结对手不会参与梯度更新。

导入后，冻结席位的抽样概率按训练路线分配：

| 对手来源 | 默认概率 |
| --- | --- |
| 当前训练路线的历史模型 | 60% |
| 外部训练路线合计 | 40% |

外部份额在训练路线之间均分，路线由模型结构和训练种子标识。每条路线内混合均匀抽样和困难度抽样，当前模型更难战胜的对手获得更高概率。未导入外部模型时，沿用原有抽样方式。概率针对每个冻结席位，单轮实际出场数会波动。

池容量仍由 `league_size` 控制，默认 12。外部模型作为固定对手保留，导入时要求至少留下四个可轮换的历史模型位置。按网络结构和权重内容去重，复制文件或修改局数不会变成新对手。

## 创建可续训的检查点

使用与当前训练相同的模拟器包。不要在训练中替换 `latest.pt`，先生成一个独立检查点：

```bash
bash rl/run.sh mix_league \
  --resume /path/to/learner/latest.pt \
  --opponents /path/to/deep256.pt /path/to/deep1024.pt \
  --external-fraction 0.4 \
  --output rl/runs/mixed-resume

bash rl/run.sh train \
  --resume rl/runs/mixed-resume/latest.pt \
  --output rl/runs/mixed-training \
  --iterations 16 --workers 8 --device cuda --rollout-device cuda
```

输出目录必须不存在。导入保留学习模型、优化器、随机数状态和累计局数。工具检查规则、观察和动作版本、实体定义、权重形状及有限值，并拒绝没有完成训练局数的对手。检查点只能来自可信训练任务。

`league.json` 记录导入文件的 SHA-256、模型指纹、来源局数和抽样概率。训练的 `manifest.json` 记录池成员，`metrics.jsonl` 的 `opponent_sampling` 记录每轮各对手的概率及实际出场席位数。

已从第 728 局、第 47 次迭代衔接，仍使用 8 个模拟器进程、每轮 16 局和 `3e-5` 学习率。来源检查点、池成员、进程及截止时间见[衔接记录](rl-deep64-diversity-20260911.json)。
