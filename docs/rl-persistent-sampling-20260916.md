# 常驻训练采样管线

2026-09-16，在 RTX PRO 6000 Blackwell、25 核 CPU 配额、120 GiB 内存容器上审查和测试。运行目录为 `/root/autodl-tmp/tavern-multi-horizon-20260916`。

## 审查结论

采样是主要耗时。原管线每个流式片段都重新启动 Python、创建模型、加载整份含 Adam 状态的检查点、启动模拟器，并把未完成对局状态经文件传回训练器。多进程按固定分组等待全部完成；深度 64、256、1024 的工作负载差异明显。

另外确认了两个统计或续训问题：

- `iteration_seconds` 和 `end_to_end_actions_per_second` 原先在保存检查点之前计算，漏计权重转移、序列化和同步写盘。
- 用已完成对局数生成下一批种子，在部分对局乱序结束后重启可能重复用种子。现在独立保存 `next_seed_offset`，旧检查点按已完成和未完成数量保守迁移。

原检查点不包含活动对局状态，文档已说明重启会丢弃未完成对局。本次保留这项行为；常驻状态只在同一训练进程存活期间续接。

## 实现

训练入口增加 `--persistent-samplers`，默认关闭，原采样模式仍可使用。

1. 每个训练器持有固定数量的常驻采样进程，通过标准输入提交任务。每轮以硬链接固定检查点版本。
2. 采样进程复用当前模型对象，使用 mmap 读取检查点并更新权重，不读取推理无需使用的优化器张量数据。当前模型的字符串编码缓存随权重加载失效。
3. 同一批流式对局期间复用冻结对手模型、真实对局模拟器和完整游戏状态。训练器只接收轨迹、标签和状态摘要。
4. 结果先写临时文件，再原子重命名为完成标志。训练器等待全部分组，按固定顺序合并，核对策略迭代号及对局种子。任一子进程出错会中止整轮并清理进程组。
5. 训练器在采样之外也处理 SIGTERM，确保在参数更新或保存检查点时停止，仍会关闭常驻进程及其 Node 子进程。
6. 检查点成功保存后再记录本轮指标，单独报告 `checkpoint_seconds`。

本版没有加入异步旧策略采样、跨训练器统一推理或改变分支根预算。固定分组仍会等待慢任务，分支模拟器也仍按调用创建和关闭。保留这些边界是为了能直接比较训练语义；不能将本版描述为已消除全部 GPU 空闲。

## 测试

新增测试覆盖真实模拟器连续两轮采样、两轮之间更新权重、常驻 PID 不变、种子游标续训、采样中断清理，以及训练器在采样完成后收到 SIGTERM 时关闭子进程。

服务器测试覆盖采样、流式状态、循环网络更新、对手联赛、分支和卡牌价值、场面及多时域价值、CUDA 采样图和训练图、fused Adam、掩码及传输。73 项主测试通过；主测试时遗漏复制掩码测试文件，补齐后其 2 项 CPU/CUDA 测试另行通过，共 75 项。原始失败记录保留，未覆盖。

三种深度各一个采样分组连续运行两轮，使用相同真实检查点、游戏快照及参考池。为控制时间，所有对照均使用 4 次配对分支试验并关闭卡牌价格探测，不执行参数更新。

| 三个分组全部完成 | 原管线 | 常驻管线 |
| --- | ---: | ---: |
| 首轮，包括初始化 | 98.99 秒 | 97.67 秒 |
| 第二轮，常驻进程复用 | 40.90 秒 | 31.34 秒 |

第二轮耗时下降约 23.4%，吞吐提高约 30.5%。这是一次固定样本对照，不是完整训练的稳定加速保证。6 份结果的轨迹、动作及分支标签一致；369,508 个浮点数中最大绝对差异为 `1.9073486328125e-6`，小于本次 `2e-6` 容差，未宣称逐位一致。

正式并发量测试使用 12 个常驻采样进程，每个分支并发 32，连续运行两轮。24 份结果与原管线对照一致，1,478,032 个浮点数中最大绝对差异同上。

此前并发扫描中，12 个临时采样进程、分支并发 32 的同一首轮耗时为 109.06 秒；分支并发 16 为 114.30 秒。24 个采样进程的预测内存加上训练器预留会超过测试预算，因此未启动。训练 batch 64/128 未显示稳定收益，且会改变优化步数，保留 32。

## 部署和运维

记录目录为 `/root/tavern-ops/20260916-resource-tuning/redesign/`。代码部署核对原文件 SHA-256，使用维护锁，备份代码并原子替换，更新运行目录校验清单。检查点备份位于该目录的 `checkpoints/`，已校验内容并移除数据盘上的备份硬链接占用。

恢复参数为三个训练器，每个 8 个真实对局 worker、4 个常驻采样进程、分支并发 32，序列 batch 32，保留训练图和 fused Adam。原截止时间仍是北京时间 16:24:41。

需要关闭常驻模式时，停止协调器并等其清理子进程，然后恢复同一检查点，移除协调器命令中的 `--persistent-samplers` 即可。保留新的种子游标与计时修复。不要对整棵训练进程树长时间使用 SIGSTOP，模拟器有 120 秒响应超时。

GPU 利用率、CPU 占用、RAM 占用不是同一个优化目标。以内存留有余量、轨迹正确、单位时间有效样本更多为验收依据，不人为填充内存或显存。

## 正式训练恢复后验证

协调器 PID `152729`，健康巡检 PID `152988`。用户随后明确要求恢复邮件，已重启邮件进程为 PID `161160`，邮件服务器在北京时间 15:41:53 接收恢复后的首封巡检邮件。

正式训练连续观测 177.45 秒，三个成员分别完成并保存迭代 `188 / 189`、`196 / 197`、`184 / 185`。每个成员两轮使用同一组采样 PID，采样策略版本均与更新前迭代号一致；12 个常驻采样进程存活，基准测试采样进程为零。

- GPU 利用率采样均值 79.54%，显存峰值 38,119 MiB，约 37.23 GiB。
- CPU 平均 15.67 核，占 25 核配额约 62.7%。
- 容器内存峰值 70.38 GiB；观测前后 OOM 计数未增加。
- 数据盘剩余约 5.18 GiB，系统盘剩余约 6.28 GiB。

真实对局路径的平均推理批量仅为 1.13–1.20。这个指标不包含分支推理，尚不能据此判断全部 GPU 工作的有效批量。各训练器每轮真实轨迹优化约 1.1–4.8 秒，检查点保存约 1.9–7.2 秒，采样约 69–115 秒。卡牌价值及分支教学不全包含在 `optimization_seconds` 中，应结合完整迭代时间判断。

随后用户允许结束训练，正式协调器已停止，三个成员最后保存的迭代为 190、199、186。之后的测试使用隔离检查点，不恢复正式训练。
