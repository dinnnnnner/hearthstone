# 采样吞吐优化

实验选项 `--packed-host-transfer` 将动作、旧策略对数概率、价值估计和 GRU 记忆合并为一个小缓冲区，
一次取回 CPU。它默认关闭，是否开启取决于实测结果。当前 4316 个动作编号可以用 FP32 精确表示；网络和 PPO 仍使用原来的精度。
超过 FP32 精确整数范围的动作空间自动使用分别传输。
冻结对手仍只计算策略，不计算价值网络。每个对局、每个席位使用独立采样随机数流。

`collect` 进度日志增加每秒动作数、平均推理批量、推理耗时和等待模拟器耗时。
并行数量可通过训练器或 `independent` 的 `--workers` 设置。
每轮对局总数、奖励、学习率、序列批量以及英雄名单继续从检查点恢复。

## 可复现的对比测试

```bash
PYTHONPATH=rl/python python -m tavern_rl.rollout_benchmark \
  --resumes /path/deep64/latest.pt /path/deep256/latest.pt /path/deep1024/latest.pt \
  --output rl/runs/rollout-benchmark.json --games 8 --steps 96
```

测试使用完整检查点、各自历史对手、保存的英雄名单及固定种子。
依次测 3 个模拟器分别传输、3/6/8 个模拟器合并传输、8 个模拟器分别传输，最后复测原配置。
也可通过 `--cases 8-separate 8-packed` 选择对比配置。
报告保存平均批量、每秒动作数、显存峰值及动作回放与基线是否一致。
其中刻意截断的短局只用于开局采样速度测试，不进入 PPO，不修改训练检查点。
结果不能代表中后期长局吞吐、PPO 更新速度或棋力提升。
共享 GPU 上的三模型总吞吐还需要从实际续训日志核对。
