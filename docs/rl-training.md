服务器是否已切换，以运行任务的 `resume.json` 和检查点中的 `config.streaming` 为准。网络结构见 [模型结构](rl-network.md)，安装见 [训练包](../rl/README.md)。

## 一次中途更新

1. 固定当前片段的策略，运行多个八人局。每席只读取自己的公开观察和独立 GRU 记忆。历史对手在这一批对局中保持不变。
2. 默认每完成两个招募回合，暂停该模拟器，等其他模拟器到达各自片段边界。保存成功执行的动作、真实概率及战斗结果。
3. 已确定名次的玩家使用真实终局回报；仍存活的玩家在下一招募回合的自身观察上估计后续价值，作为 GAE 的 bootstrap。截取片段不是输局，不产生虚构名次。
4. 抽取少量有经济选择的局面，恢复完整快照，分别尝试买牌、升本、刷新和卖牌。分支继续推演若干回合，比较后续价值。
5. 用原对局片段做 PPO，并训练近期战斗和资源预测；再用分支比较的软标签辅助训练策略。
6. 保存参数。用新权重重放每个学习席位已发生的公开观察历史，重新计算 GRU 记忆，从原局面继续游戏。

采样与参数更新分开执行。分支第一步是人为指定的，不能当作策略正常抽样的动作进入 PPO。分支数量也不计入完整对局数。

`episodes` 只统计真正结束的八人对局；`iteration` 在持续模式下统计中途更新轮数。`--iterations` 仍控制本次完成多少批完整对局，每批有 `games_per_iteration` 局，所以一次批次可能产生多轮中途更新。历史池和模型间对手交换在完整批次结束后进行。

每次中途更新都会保存模型、优化器及已经完成的局数。活跃对局快照在采样进程之间传递，但当前不写进长期模型检查点；停止或重启会放弃尚未结束的局面，保留已经完成的参数更新，不给这些局面补造最终名次。

## 比较是否公平

候选从同一份完整快照出发，模型、对手、金币、牌面、血量和牌池一致。未来环境随机数按试验编号配对，每席动作抽样使用独立随机流。不同动作会消耗不同数量的随机数，因此不能保证以后出现完全相同的酒馆和战斗结果。

完整快照只用于模拟。其他席位的私有手牌和当前阵容不会直接进入策略输入。

候选优先覆盖结束、升本、刷新、买随从、卖随从、购买法术和出牌。每类先选策略概率最高的一项，再按与策略概率无关的顺序轮换补入其他合法买卖选择。低概率卡牌也能接受比较，但单个局面不穷举所有组合。冻结和换位继续由完整对局学习，不占经济比较预算。

每个候选取多个结果的均值。报告保留相对根局面中最高概率候选的配对收益差与标准误差。均值经温度 softmax 转成标签，再与冻结策略先验混合，默认比较标签占25%。标准误差也用于决定是否追加采样；当前没有实现统计显著性门槛。

短分支的结果是价值网络估计，会继承价值网络的误差；完整分支使用实际名次。报告区分两者，不能把估值当作实测胜率。价值网络使用真实奖励和未结束片段的 bootstrap 训练；对局结束后得到的真实名次继续校准估值。

只有全部候选的全部试验完成，该局面才生成标签。任一分支达到步数上限或被截断，整组比较都不进入辅助训练，避免偏向更容易算完的选择。

## 默认预算

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| `--branch-roots` | 1 | 每采样进程、每轮保留的局面数 |
| `--branch-candidates` | 8 | 每局面的候选上限 |
| `--branch-min-trials` | 4 | 每候选先进行的配对试验数 |
| `--branch-trials` | 12 | 每候选试验上限 |
| `--branch-workers` | 16 | 每采样进程的分支并发上限 |
| `--branch-horizon` | 2 | 短分支向后推演的招募回合数 |
| `--branch-terminal-fraction` | 0 | 持续模式默认短推演，真实终局来自持续运行的原对局 |
| `--stream-turns` | 2 | 两次更新之间完成的招募回合数 |
| `--branch-max-steps` | 6000 | 每分支的整桌动作上限 |

四个采样进程每次更新最多保留四个局面，最多8×12×4=384个分支。先比较4组配对结果，结果仍接近或波动较大时再追加，最多12组；不是每个候选固定算12次。提前停止是计算预算规则，不是统计上的可靠性保证。原对局会继续到真实结束，短分支也可能提前产生真实淘汰名次。单独启用 `--counterfactual` 而不启用持续模式时，仍保留完整对局 PPO 和默认0.25的终局分支比例。

分支阶段复用已有网络和空闲模拟器，需要时临时增加 Node 进程组成推理批次，结束后关闭。三个深度各自训练，需要合计全部进程的预算。

## 从现有模型切换

先正常停止占用输出目录的训练进程，并保留检查点副本。以下命令不会发布客户端模型：

```bash
bash rl/run.sh train --output rl/runs/deep64 \
  --resume rl/runs/deep64/latest.pt --iterations 100 \
  --streaming --stream-turns 2 --tier-tempo --branch-roots 1 \
  --branch-min-trials 4 --branch-trials 12 \
  --branch-candidates 8 --branch-workers 16 --branch-horizon 2 \
  --branch-terminal-fraction 0 \
  --workers 8 --sampling-processes 4 --device cuda
```

`--streaming` 或 `TAVERN_STREAMING=1` 启用持续模式，自动启用同局面分叉，移除旧金币直接搜索和手写阶段奖励配置。主体网络、已有参数、Adam动量、局数和历史池保留；新增辅助预测参数从零初始化。当前要求 `gamma=1`，续训继承已保存配置。

64、256、1024层使用同一入口，各自加载检查点。实体输入和动作编号不变，增加一个轻量辅助输出层；不用重新训练主体网络。含辅助头的新检查点需要本版 Python 模型加载代码，不能直接交给旧版推理程序。

## 奖励

```text
终局回报 = (4.5 - 名次) / 3.5 + 第一名额外奖励 × 是否第一名
```

现有服务器任务第一名额外奖励为1，对应第一名+2、第八名−1。新建任务省略 `--first-place-bonus` 时默认为0，续训继承保存值。

结束回合剩余金币扣分已移除。没有升本次数、刷新次数、花光金币或必须抓某张卡的固定奖励。模型读取回合、金币、升本费用、场上和手中的卡牌，从不同选择的后续收益学习取舍。

按用户要求，增加可选的7～8回合升本节奏目标。`--tier-tempo` 或 `TAVERN_TIER_TEMPO=1` 在持续模式启用：第8回合实际战斗结束后仍存活，4本获得0.05，5本及以上获得0.075；一局只检查一次。没有达到目标不扣分，之后升本不补发，也不限制任何合法操作。该奖励远低于第一名2分，允许模型根据血量、场面和费用选择先稳住。普通训练默认不开启，续训继承检查点配置，可用 `--no-tier-tempo` 关闭。

真实轨迹和分支使用相同的节奏奖励。分支只加从根局面往后实际跨过第8回合产生的奖励，短分支再加边界处后续价值；第9回合以后不会重复计算已经获得的奖励。此时价值网络预测的是剩余节奏奖励加最终名次回报。`metrics.jsonl` 的 `tier_tempo_checks` 记录第8回合各席等级、血量和奖励；分支报告另记 `tempo_rewards`。需要用这些记录衡量是否真的更早进入4、5本，不能把奖励启用当作已经学会。

持续模式另有辅助预测损失，权重为0.1，不直接改变游戏奖励：

| 预测目标 | 真实标签 |
| --- | --- |
| 下一战胜、负、平 | 该回合实际战斗结果 |
| 战败受到的伤害 | 战斗记录中的伤害，除以40 |
| 下一回合额外到账金币 | 回合开始后的金币超出常规收入的部分 |
| 手牌与场上牌储备 | 下一回合开始时分别有多少张牌 |
| 免费刷新、法术折扣、后续金币信用 | 下一回合实际状态中的对应资源 |

经济资源分别预测，使用 `log1p` 缩放，没有合成一个“总金币”分数，也不奖励囤牌。卡牌种类、金色状态和效果仍在实体输入中，由长期价值与不同买卖方案比较学习机会成本。当前资源头预测储备量，不等于完整估计所有产牌、折扣触发及循环收益。

阶段反馈模块作为独立实验保留，与持续模式互斥。持续模式只保留上述可选的一次升本节奏奖励，不按每回合场面大小持续发奖励，也不能把短分支估值当作已测准的卡牌经济价值。

## 逐牌金币估值

可在持续模式加 `--card-value`，用同局面的卡牌与现金替换比较训练每张随从的金币等价估值，并将估值输入买牌、出牌、卖牌决策。估值依赖阵容和回合，已经触发的战吼收益不会重复算入剩余牌面价值。它是独立辅助任务，不改变真实对局奖励。具体采样、上下界和误差说明见 [逐牌估值](rl-card-value.md)。

## 真人示范与历史对手

已有模仿学习得到的权重可作为起点，再通过自我对局和分叉比较改进。无需把人的每一步当成最优答案。

旧真人记录只有公开观察、合法动作和实际选择，没有完整整桌快照和牌池，无法精确恢复当时对局。因此这版从模拟器生成的局面分叉，没有伪造旧真人对局状态，也没有自动重新拟合全部示范。数据与模仿入口见 [真人示范](rl-human-demonstrations.md)。

三种深度分别维护权重、优化器和历史池。现有混合配置通常四席为当前学习策略，四席从冻结网络抽取；冻结席位约60%来自本模型历史、40%来自另外两种深度。协调器每两轮交换其他模型的新快照，不平均参数。详细机制见 [对手多样性](rl-opponent-diversity.md)。

PPO按每席连续决策计算GAE。常用设置是 `gamma=1`、GAE lambda 0.95、clip 0.2、价值系数0.5、熵系数0.01、梯度上限0.5、目标KL 0.03。序列前的 burn-in 恢复记忆，填充位置不进入损失。

旧的 `--gold-planning --planning-direct` 模式仍保留，使用本回合搜索直接选动作，再训练搜索策略和价值。它与新模式互斥，见 [金币规划](rl-gold-planning.md)。客户端在线搜索独立运行，修改训练流程不会自动更新网页权重。

## 验证结果

检查 `metrics.jsonl` 的完整对局数、中途PPO更新、辅助损失、`streaming_active_games`、分支标签数和截断数。游戏没结束时出现 `episodes=0`、更新轮数增加，是持续模式的正常行为。每轮 `counterfactual-*.json` 保存公开局面、具体候选、每次结果、均值和配对差异，可查看某张牌在什么局面被评为更好。

速度同时看整轮耗时与分支耗时，不能用GPU百分比替代吞吐。棋力使用未参与训练的种子和固定冻结对手，比较平均名次、前四率和第一率。八席同模型的整桌平均名次恒为4.5，不能作为进步指标。流程测试通过不代表棋力已经提升。

多时间尺度训练使用 1、3、5 回合后继预测和按回合匹配的参照对手，见 [多时间尺度场面与经济预测](rl-multi-horizon.md)。
