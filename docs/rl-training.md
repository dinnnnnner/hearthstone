# 训练流程、奖励与评估

本页说明当前代码的训练方式。带日期的实验记录保存当时的配置和结果；正在运行的局数、版本与截止时间以 `python3 scripts/tavern-ops.py status` 为准。网络细节见 [模型结构](rl-network.md)，安装命令见 [训练包](../rl/README.md)。

## 一轮 PPO 做什么

1. 冻结本轮当前策略和历史对手，启动多个八人模拟器。
2. 每个席位按自己的观察和 GRU 记忆选择动作，规则引擎结算招募、配对、战斗与淘汰。
3. 只收集由当前策略控制的席位轨迹。历史对手动作参与环境推进，不进入当前模型的 PPO 数据。
4. 等本轮指定数量的完整对局结束，按每个玩家自己的决策顺序计算 GAE 和回报。
5. 将轨迹切成连续序列，进行策略、价值和共享编码器更新。
6. 保存完整检查点和指标，将当前权重加入历史池，再开始下一轮。

`episodes` 统计完整八人对局，`iteration` 统计 PPO 轮数，`samples` 统计学习席位的决策记录。一次八人对局会贡献多个学习席位的轨迹，这三个数字不能互换。

达到整局步数上限仍未结束时，训练报错并保存诊断，不编造最终名次，也不把截断局送入本轮 PPO。每席位每回合默认最多 64 次普通决策，随后完成必要选择并结束招募。

## 三个模型怎样混合

64、256、1024 层各有自己的权重、优化器、历史池和训练局数。每个模型的一局通常四席使用自己的当前策略，四席使用冻结网络。冻结席位按以下概率取对手：

| 来源 | 占冻结席位的抽样概率 |
| --- | ---: |
| 本模型的历史快照 | 60% |
| 另一深度模型的快照 | 20% |
| 第三种深度模型的快照 | 20% |

比例对应外部对手总占比 0.4、有两条外部路线的当前配置，是抽样概率，不要求每一局严格分成固定人数。各来源内部混合均匀抽样和基于历史相对名次的困难度权重。它不是独立测得的 Elo。

历史池默认上限 12，保留锚点及分散的历史版本。当前三模型协调器每完成两轮 PPO 就导入其他模型最近保存的冻结权重，每条外部路线最多保留两版；各模型不必等待另外两条路线同时结束。初始化时没有可用历史对手的第一轮，会让八席都由当前随机策略控制。

交换对手不会平均三个网络的参数，也不会把其他网络的旧动作当成本策略样本。真人模仿记录会随检查点保留，但当前四小时自我对战阶段没有同时混入新的真人行为克隆更新。

工具与测试细节见 [对手多样性](rl-opponent-diversity.md) 和 [群体训练](rl-population.md)。

## 奖励

规则引擎的基础终局分数为：

```text
基础分 = (4.5 - 名次) / 3.5
PPO 回报 = 基础分 + 第一名额外奖励 × 是否第一名
```

当前服务器续训显式使用 `first_place_bonus = 1`：

| 名次 | PPO 终局回报 |
| --- | ---: |
| 1 | +2 |
| 2 | +0.714286 |
| 3 | +0.428571 |
| 4 | +0.142857 |
| 5 | −0.142857 |
| 6 | −0.428571 |
| 7 | −0.714286 |
| 8 | −1 |

第一名比第二名多约 1.286，其他相邻名次差约 0.286。游戏名次和评估指标不因额外奖励而改变。源码新建训练省略 `--first-place-bonus` 时为 0；续训省略时继承保存值，运维脚本会明确传 1。

结束回合剩余金币扣分已删除。采样不再维护对应逐步奖励列表，也不再每动作计算扣分或统计；旧检查点里的惩罚配置在恢复时移除。现在只有终局排名回报，包括可配置的第一名加分。

没有额外的买牌、升本、攻击生命增长、寻找核心卡或花光金币奖励。这些动作只能通过对最终名次的影响获得学习信号。模型能看见回合和经济状态，但长期回报较稀疏，不能保证训练后自然形成指定节奏。历史变更见 [奖励迁移](rl-unused-gold-penalty.md)。

## 序列 PPO 和当前配置

每个学习席位分别计算优势。默认 `gamma = 1`、GAE lambda 为 0.95。训练序列前的 burn-in 片段不计算梯度，用于恢复记忆；正式序列按顺序更新 GRU，填充位置不参与损失。

优化目标包含 clipped PPO 策略损失、价值均方误差和熵奖励。clip 为 0.2，价值系数 0.5，熵系数 0.01，梯度范数上限 0.5。目标 KL 为 0.03，超过其 1.5 倍时提前结束后续更新。

下表是 2026-09-15 Blackwell 四小时任务的配置，不是全部 CLI 默认值：

| 项目 | 每个模型的设置 |
| --- | --- |
| 网络宽度 / Transformer | 128 / 两层、四头 |
| 学习率 / PPO epochs | 0.00003 / 2 |
| 每轮对局 / Node 模拟器 | 64 / 64 |
| Python 采样进程 | 8 |
| 学习席位 / 历史席位 | 4 / 4 |
| 序列长度 / burn-in | 16 / 8 |
| 每次更新序列数 | 32 |
| 第一名额外奖励 | 1 |
| 英雄池 | 已实现的 15 英雄暂定名单 |
| 精度与执行 | FP32、融合 Adam、残差分支 CUDA Graph |

三个模型合计 24 个 Python 采样进程、192 个 Node 模拟器，通过独立 MPS 管道并发使用 GPU。服务器有约 96 GB 显存、25 核容器 CPU 配额、120 GiB 内存。当前配置及命令见 [运维说明](tavern-operations.md)。

## 怎样提升训练效率

先查看 `metrics.jsonl` 中采样耗时、更新耗时和完整一轮的吞吐。模拟器依赖 CPU，字段整理和 Python 调度也会限制 GPU 供给；只看 GPU 百分比无法判断实际训练速度。

目前实现了多进程采样、批量模型推理、采样 CUDA Graph、残差分支训练 CUDA Graph、融合 Adam，以及数值编码缓存。各进程一轮内使用同一冻结策略，PPO 更新仍在完整采样批次之后。

Blackwell 短采样实测最高为原单进程约 5.30 倍，这是固定短轨迹的采样测试，不是整轮训练加速比。更大的序列批量会改变每轮优化器更新次数，需要同时关注 KL、损失和棋力。资源占用随采样、PPO 和检查点交换阶段变化，不需要通过额外分配把内存占满。原始条件和结果见 [性能记录](rl-blackwell-20260915.md)。

## 真人模仿学习

网页提供主动录制入口，仅记录实际成功的玩家操作、对应公开观察和合法动作。记录可能从中途开始，也可能在自动操作处中断，因此按连续片段处理，不能跨断点拼接记忆。

模仿目标是提高示范动作的概率。低学习率和有限更新可以减轻过拟合，但不会自动识别哪一步是失误。反复拟合同一批对局可能降低训练损失，却不改善升本、找牌或对局名次。

接入正在训练的模型时，先停止对应训练进程，使用完整 PPO 检查点做模仿，验证后再恢复自我对战。流程保留原 PPO 优化器、局数、随机状态与历史对手；模仿使用独立优化器并记录数据指纹。不能在旧进程仍运行时直接覆盖文件，否则后续保存会覆盖模仿结果。

具体工具、数据检查和历史记录见 [真人示范](rl-human-demonstrations.md)。没有另行发布时，模仿与续训都不会自动更新网页。

## 搜索和训练的关系

三种深度均有独立的在线搜索选项。搜索只模拟自己的当前招募回合，使用公开状态估计卡池，最多 32 次模拟、128 个节点、单条路径 64 步，默认软时间预算 1000 毫秒。单个同步调用可能超出剩余预算。

搜索依赖现有策略与价值估计，当前没有把搜索访问分布蒸馏进模型，也没有在 PPO 采样中启用搜索。功能测试和请求时延不能证明搜索版棋力更高。完整信息范围、回退条件和部署端口见 [搜索说明](rl-recruit-search.md)。

## 如何判断训练有效

使用固定冻结对手和未参加训练的种子，让候选模型占一个席位，统计平均名次、前四率、第一率和误差。比较旧、新模型时保持对手集合、种子、规则和决策预算一致。

八席使用同一模型时，整桌平均名次恒为 4.5，不能作为进步指标。混合训练的对手持续变化，训练平均名次也不是固定难度的考试。模仿损失降低只能说明更贴近示范，更多层数、更多局数和更高利用率也都需要棋力评估支撑。

当前小规模验证主要覆盖合法动作、规则兼容、稳定性和执行速度，尚不能给出三种深度之间可靠的棋力排序。
