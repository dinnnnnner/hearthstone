# 采样期间缓存残差网络的 GPU 运算

`SimulationPool.collect` 现在通过 `accelerate_sampling` 装饰器，在 CUDA 采样期间缓存策略塔和价值塔的运算图。每个塔使用模拟器数量作为固定批量，小批次补齐后只取真实样本对应的输出。残差塔中的 Linear、LayerNorm 和 SiLU 都逐行计算，补齐行不会参与其他样本的计算。

牌面编码、循环记忆、合法动作、每个座位的随机数流、历史对手分配和对局调度仍执行原来的代码。参数和计算精度没有改变。对手只计算策略塔；学习者还计算价值塔。

运算图只存在于一次采样调用期间，退出时恢复原来的 `forward` 并释放缓存。PPO 使用正常的自动微分路径，下一次采样会根据更新后的参数重新捕获。CPU、带梯度的调用和自动混合精度调用使用原路径。实现参考 [PyTorch CUDA Graph 文档](https://docs.pytorch.org/docs/2.14/notes/cuda.html#cuda-graphs)。

## 使用和关闭

CUDA 采样默认启用。通过环境变量关闭：

```bash
TAVERN_SAMPLING_GRAPHS=0 PYTHONPATH=rl/python python -m tavern_rl.train ...
```

训练完成一轮后，指标会记录 `sampling_graph_count`、`sampling_graph_replays` 和 `sampling_graph_capture_seconds`。采样吞吐包含捕获、执行和释放的时间。

可用固定检查点对比采样速度：

```bash
PYTHONPATH=rl/python python -m tavern_rl.sampling_benchmark \
  --checkpoint /path/to/latest.pt --output /tmp/sampling.json \
  --workers 16 --games 16 --steps 256
```

默认按原路径、运算图、原路径测试。`--steps 0` 使用训练配置中的完整对局上限。测试读取同一份模型和历史对手，不更新检查点；每个种子的动作回放必须一致。截断测试只用于计时，不用于 PPO。

旧的冻结运行目录可用 `scripts/enable-sampling-graphs.py` 安装。它只添加导入和装饰器，保留目录里已有的第一名奖励等扩展，并备份修改前的文件。

## 验证范围

本地测试覆盖 CPU 和梯度路径、异常退出恢复、补丁重复执行和关闭开关。租用服务器的 CUDA 测试还覆盖不同批量、输出不会被后续调用覆盖、参数更新后重新捕获，以及采样日志概率在 PPO 中的重放一致性。零学习率 PPO 重放的近似 KL 小于 `1e-6`。

服务器验证文件位于 `/root/tavern-sampling-20260915`。短对局初测中，1024 层模型的采样从约 37 提升至 85 动作/秒，16 个种子共 1024 次决策的动作回放一致，额外峰值张量显存约 114 MiB。该初测与正式训练同时运行，不作为最终吞吐结论。

用户随后要求停止正式训练。2026-09-15 09:26 停止时，64、256、1024 层分别保存至 2696、2268、1380 局。第一名额外奖励为 1，剩余铸币惩罚为每枚 0.01。

停止训练后，1024 层模型用相同权重和历史对手完成了四局完整对照，共 6176 步、16 条学习轨迹。优化前后所有动作回放一致，均无截断，剩余金币惩罚的次数与总额也一致。采样耗时由 334.66 秒降到 136.41 秒，速度约为原来的 2.45 倍。峰值张量显存由 1348.06 MiB 增至 1437.62 MiB。该测试只运行一个学习者，且只同时采样四局，用于覆盖完整对局行为，不能直接代表三个学习者持续训练的速度。

优化已安装至 `/root/autodl-tmp/tavern-mixed-popular-20260914/rl/python/tavern_rl`。安装备份和哈希在 `/root/tavern-sampling-20260915/deployment-backup` 和 `deployment.json`。`train.py` 未变，正式训练保持停止；下次使用原有续训命令时会自动启用。

## 三模型同时采样的结果

正式训练停止后，让三个模型在同一张 RTX 3080 Ti 上同时采样。每个模型使用 16 个模拟器、相同的 16 个种子和冻结的混合历史对手，每局执行 256 步。按原路径、优化路径、原路径顺序测试，基线取首尾两次动作吞吐的平均值。

| 模型 | 原采样，动作/秒 | 优化后，动作/秒 | 速度比 |
|---|---:|---:|---:|
| 64 层 | 79.30 | 114.38 | 1.44 倍 |
| 256 层 | 67.06 | 114.08 | 1.70 倍 |
| 1024 层 | 37.47 | 102.79 | 2.74 倍 |

三组测试的每个模型、每个种子，动作回放全部一致；检查点文件哈希也保持一致。优化后三个进程各自的峰值张量显存增加约 106、98、114 MiB。定时监测的 GPU 总显存最高约 4.8 GiB，未发生内存不足。

计时包含采样中的运算图捕获和释放，不包含检查点加载与 PPO 更新。三个模型同时开始，各自完成后退出。因此表格表示本次采样测试的速度比，不能直接视为完整训练的提速或棋力提升。完整原始结果、脚本和部署哈希见 [同名 JSON](rl-sampling-graphs-20260915.json)。
