# 集中推理实测

2026-09-16，接续[常驻采样改造](rl-persistent-sampling-20260916.md)。用户允许结束训练后，已停止正式协调器并清理其采样进程。三个成员最后保存的迭代为 190、199、186；本轮测试使用隔离的旧检查点和参考池，不执行参数更新。

## 架构与边界

每个训练器启动一个 GPU 推理服务。CPU 采样进程持有模拟器、每座位随机数和循环网络状态，通过私有 Unix socket 通知服务读取 mmap 缓冲区。模型和冻结对手仅由服务加载，减少采样进程之间的重复显存占用。

CPU 预先打包实体特征。服务只合并权重版本、模型、价值输出和先验需求均一致的请求，批大小与等待时间有上限。抽样仍在 GPU 使用原掩码 CDF 和座位随机数；轨迹按固定分组顺序返回。每轮更新前等待全部采样结束，下轮重新加载权重并更换版本标识，拒绝旧版本请求。

卡牌价值预测和循环状态重算经过同一服务。服务异常退出会使当前整轮失败，并清理采样进程和模拟器。SIGTERM 清理也覆盖训练器在采样之外的阶段。

这是每个训练器内部共享模型的实现，没有跨三个训练器混合权重，也没有异步旧策略采样。每个服务当前串行执行 GPU 请求；单个 CPU 采样进程仍等待自己的请求完成，尚未改成逐对局异步调度。直接规划和阶段反馈模式暂不支持该开关。

## 固定样本测试

服务器为 RTX PRO 6000 Blackwell，CPU 配额 25 核，容器内存 120 GiB。测试独占采样工作负载，不同时运行训练器。12 个采样进程分成三个模型组，每个分组使用 2 个真实对局、32 个分支模拟器。为缩短参数扫描，配对试验为 4 次，关闭卡牌价格探测，保留场面和多时域价值。各模型组内重复同一固定样本；后面的完整配置测试使用不同种子。

| 配置 | 首轮秒数 | 第二轮秒数 | 首轮动作/秒 | 第二轮动作/秒 | 显存峰值 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 常驻采样，12 进程 | 108.88 | 42.60 | 573.27 | 481.21 | 25,935 |
| 集中推理，batch 16，等待 0 ms | 127.24 | 45.17 | 490.53 | 453.80 | 6,412 |
| 集中推理，batch 32，等待 1 ms | 140.27 | 46.93 | 444.98 | 436.80 | 6,756 |
| 集中推理，batch 64，等待 1 ms | 146.23 | 46.34 | 426.85 | 442.39 | 6,984 |

每项首轮都有 2,684 个真实动作和 59,732 个分支动作，第二轮有 4,096 和 16,404 个动作。首轮包含初始化，第二轮复用进程和流式状态；不能用两轮间的耗时差计算加速。

batch 16 的采样显存下降 75.3%，首轮耗时却增加 16.9%，第二轮增加 6.0%。batch 32 的首轮 GPU 利用率均值达到 71.37%，高于原版的 64.49%，但吞吐更低。这组结果直接说明 GPU busy 百分比不能代替有效样本吞吐。

将集中推理扩展到 24 个 CPU 采样进程、每进程分支并发 16，使分支模拟器总上限仍为 384。每个模型组的固定样本副本翻倍，实际工作量也翻倍；不是同工作量耗时对照。

| 24 进程、batch 16、等待 0 ms | 首轮 | 第二轮 |
| --- | ---: | ---: |
| 用时 | 215.67 秒 | 64.48 秒 |
| 真实动作 / 分支动作 | 5,368 / 119,464 | 8,192 / 32,808 |
| 合计动作/秒 | 578.80 | 635.90 |
| 平均 CPU 核数 | 18.58 | 22.43 |
| 容器内存峰值 | 63.79 GiB | 62.94 GiB |
| 显存峰值 | 6,412 MiB | 6,524 MiB |
| GPU 利用率采样均值 | 63.46% | 58.54% |

相对常驻 12 进程，首轮吞吐增加约 1%，第二轮增加约 32%；合并两轮的总动作吞吐增加约 8%。工作负载是重复固定样本，且没有训练器、卡牌价格探测与参数更新，不能据此承诺完整训练加速 32%。

## 完整采样配置

另取三个成员各 8 个不同种子，从新对局开始，运行一个两回合流式片段。保留正式配置中的 12 次分支试验、卡牌价格探测、场面与多时域价值；不执行 PPO 或辅助头更新。两侧真实动作均为 1,214，普通分支动作 15,322，卡牌探测分支动作 33,648，共 50,184 个动作。6 个卡牌探测产生 648 条分支及 2 个有效训练标签。

| 相同 24 个种子、12 个采样进程 | 常驻采样 | 集中推理 batch 16 / 0 ms |
| --- | ---: | ---: |
| 完成用时，含初始化和结果落盘 | 100.93 秒 | 111.29 秒 |
| 容器内存峰值 | 62.11 GiB | 49.76 GiB |
| 显存峰值 | 25,827 MiB | 7,472 MiB |
| GPU 利用率采样均值 | 71.77% | 63.55% |

同并发量的完整配置耗时增加约 10.3%，显存下降约 71.1%。该项只测一个流式片段，没有给出完整训练长期吞吐结论。

同样 24 个种子改为 24 个采样进程、每进程分支并发 16 后，用时 170.32 秒，显存峰值 7,710 MiB，容器内存峰值 53.77 GiB，GPU 利用率均值 76.40%。实际处理 1,214 个真实动作、42,529 个普通分支动作、54,473 个卡牌探测动作。分支根预算和探测选择作用于各采样进程，改变分组也改变了教学工作量：这项不是同工作量速度对照，不能把增加进程数视为完全不影响训练配置的改动。

## 正确性与验收

对 12 进程扫描的 72 份结果和完整配置的 3 份结果进行递归比较：动作、种子、游戏状态及其他离散数据均无差异。共比较 4,626,094 个浮点值，最大绝对差异为 `4.291534423828125e-6`。沿用前一阶段的 `2e-6` 绝对阈值时有 66 处超限，集中在动作 log probability 和循环网络记忆；没有放宽阈值或把这项检查记为通过。原始失败报告保留在远端 `central/validation-results.json` 和 `central/validation.log`。

本地 93 项回归测试通过，其中 6 项 CUDA 测试因本地无 GPU 跳过。远端首次运行受正式训练的 `TAVERN_STREAMING`、`TAVERN_TIER_TEMPO` 环境变量影响，且隔离目录漏放一个测试需要的脚本，出现 3 个失败、1 个错误。已补齐脚本，并将单元测试环境与正式训练环境分离；原始日志保留为 `first-tests.log`。性能测试保留正式环境，未用单元测试环境重写性能结果。

## 使用方式

新代码位于本地源码和远端隔离目录 `/root/tavern-ops/20260916-resource-tuning/central/rl/python/`，未替换正式运行目录。集中推理开关默认关闭。实验代码中显式启用需要常驻采样和至少两个采样进程，例如在原训练命令上增加：

```sh
--persistent-samplers --central-inference --inference-max-batch 16 --inference-delay-ms 0
```

同时保留原命令中合法的 `--sampling-processes` 和 `--workers` 配置。该示例只指定推理模式，不是重启训练命令；本轮结束后正式训练保持停止。

本轮不部署集中推理：同并发量的完整配置变慢，严格数值对照也未通过。正式环境保留已经验证的常驻采样方案；训练按用户要求保持停止。新的架构已完成实现和实验，但尚不能承诺提高完整训练吞吐或将 GPU、CPU 同时保持满载。
