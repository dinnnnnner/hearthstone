# 用实战对局做模仿学习

公网页面在“实战样本”中提供“记录我的操作，用于模型训练”开关，默认关闭，浏览器记住选择。勾选后新建人机对局，开局状态显示录制已开启。好友房和离线练习暂不录制。再次开局沿用房间设置。建议使用不限时训练模式并手动结束每个招募回合。

服务端以玩家实际成功执行的操作为准，记录操作前的可见观察、合法动作集合、动作编号、上一步动作、回合、金币、手动结束时未用金币，以及淘汰时的最终名次。对局按玩家完整序列保存，不保存昵称、登录凭据、房间码或其他玩家私有手牌。记录的是当前输入格式的训练样本，不是可以从随机种子重新播放的完整模拟器录像。

`server/demonstrations.ts` 使用与 `scouting-v4` 推理相同的观察编码和动作定义。默认站位、法术出牌和英雄技能会转换成对应的动作编号。请求重试不重复记样本，失败操作不记录。录制采用有序异步 gzip 追加写入，不调用模型或训练进程。

服务由 `TAVERN_DEMONSTRATIONS=/var/lib/bobs-tavern/demonstrations` 开启，每种输入契约单独一个目录，包含 `schema.json` 和每个玩家序列的 `.jsonl.gz`。文件不在网站目录内，只能经服务器账户读取。目录权限为 0700、文件权限为 0600。总数据预算为 1 GiB、待写队列上限 4 MiB、单序列上限 4096 步。达到限制会停止记录相应数据并计入错误，不阻断游戏操作；归档腾出空间后需重启服务重新计算占用。

`/tavern-api/health` 的 `recording` 显示启用状态、序列数、动作数、完整数、排除数、写入错误数和占用字节；`/models` 的 `recordingAvailable` 控制网页开关可用性。录制开启不代表已经训练或替换模型。

以下情况保留记录但不进入默认训练集：中途启用或恢复、离开房间、自动结束回合、脚本接管、观察/动作无法编码、服务重启、缺少终局或写入缺段。玩家正常淘汰且名次确定后，其自身完整序列可用，不必继续观看其他人的比赛。写入错误或异常退出留下的残缺 gzip 文件也会被数据读取器拒绝。

## 独立试训

`rl/python/tavern_rl/demonstrations.py` 校验输入契约、动作合法性、实体位置、连续步号、上一步动作和终局标记。完整对局按 gameId 划分训练集与验证集，同一场对局不能出现在两边。至少需要两个完整对局；这只是运行门槛，不代表数据量足以提高棋力。实际划分和文件 SHA-256 保存到试训报告中。

`rl/python/tavern_rl/imitate.py` 读取已导出的推理权重，按人的操作做负对数似然训练。每个深度单独计算自身的 GRU 记忆，按当前权重从序列开头重建，不复用其他模型的隐藏状态。试训只增加策略监督，不把人类操作伪装成 PPO 的在线采样，也不训练价值头。默认只更新 8 次，学习率为 1e-5，梯度范数上限为 0.5。

```sh
PYTHONPATH=rl/python .venv/bin/python -m tavern_rl.imitate \
  --checkpoint /path/to/exported/model.pt \
  --dataset /path/to/demonstrations/CONTRACT \
  --output /path/to/new-trial
```

输出目录必须不存在，生成 `candidate.pt` 和 `report.json`。候选权重使用新的模型标识，并记录原检查点标识。训练局数不会因为模仿学习更新而冒充增加。这是独立推理候选文件，不含可直接恢复 PPO 的优化器或历史对手池。继续自我对战训练需要另行导入策略并初始化相应训练状态。

仅学习指定的一局时，将该局和 `schema.json` 放入单独的数据目录，并添加 `--single-game`。目录必须恰好包含一条通过校验的玩家序列，不能混有被拒绝的文件。此模式没有独立验证集，报告中的 `validation` 为 `null`，学习前后指标只表示对这局操作的拟合程度。

如果该局已取得最终名次，但因为 `capture_gap` 或 `automatic_end` 被标为不完整，可以显式添加 `--single-game --allow-incomplete-prefix`。读取器从真实开局逐步检查观察中的回合内决策计数、上一步动作，以及跨回合前的手动结束动作，只保留第一个缺口之前的连续前缀。缺失动作和缺口后片段都不补入训练；原始文件和不完整终局标记保持原样，报告记录原始步数、保留步数和排除原因。中途录制、离开、重启、缺少最终名次等记录仍被拒绝。默认模式仍只使用完整对局。

需要学习缺口后的已记录操作时，改用 `--single-game --allow-incomplete-segments`，不能与前缀选项同时使用。读取器先校验全部记录的观察和动作合法性，再根据决策计数和结束回合动作拆分连续片段。每个片段单独从零 GRU 记忆和初始动作标记开始，训练块只回放自己所在片段的历史。缺失动作不推测、不补造；片段开始时的历史记忆是近似值，学习前后评估也使用相同的重置方式。原始记录中的 `previous` 和终局标记不改写，初始动作标记只用于训练副本。

分段模式报告每段原始步号范围、训练块数 `trainingChunks` 和实际参与梯度更新的不同操作数 `uniqueSupervisedSteps`。更新次数至少达到训练块数时，全部片段都会被训练一次；默认 8 次更新不保证覆盖长对局。可从已有候选继续训练，元数据分别记录本次更新数与累计模仿更新数。

若记录从对局中途开始，但已记录最终名次，可额外使用 `--allow-partial-start`。此选项必须与分段模式一起启用，首段也从零记忆开始，报告保留 `partialStart` 和 `firstRecordedTurn`。默认分段模式仍拒绝中途开始的记录；缺少最终名次、因服务重启而截断等情况不会因此放行。不会拼接不同录制序列或补造开局操作。

计算机 `100.97.24.15` 已安装试训工具，路径为 `~/.local/share/tavern-imitation/releases/20260914`。在该目录运行时设置 `PYTHONPATH=python`，解释器使用 `~/.local/share/tavern-models/venv/bin/python`。公网采集的数据需由管理员经 SSH 复制到计算机，当前不会自动下载或触发训练。

报告给出训练与验证集的动作一致率、负对数似然、更新次数和实际改变的张量数。验证集与人类操作更一致不等于棋力提高；上线前仍需单独对战评估，当前流程不自动替换公网模型。
